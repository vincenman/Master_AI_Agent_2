## Fix PDF export crash: xhtml2pdf str/bytes TypeError

**Symptom:** `TypeError: sequence item 0: expected a bytes-like object, str found` in `xhtml2pdf/reportlab_paragraph.py:127` (`_justifyDrawParaLine` → `b" ".join(words)`) during `_export_pdf()`.

**Root cause:** xhtml2pdf 0.2.17's paragraph renderer mixes `str` and `bytes` word types in its CJK line-breaking path. All four draw helpers (`_leftDrawParaLine`, `_centerDrawParaLine`, `_rightDrawParaLine`, `_justifyDrawParaLine`) join words with `b" ".join(...)` and crash when a line's word list contains a `str`. It is content-dependent (the previous 台積電 export worked; the new report's paragraph shapes — e.g. a page-split continuation of a paragraph with inline markup like `**bold**`/highlight spans — hit the mixed-type path). Removing `text-align: justify` would NOT fix it, since the left/center/right helpers have the identical join. Dropping `-pdf-word-wrap: CJK` would reintroduce the text-clipping bug.

## Change (one file: `src/financial_researcher/main.py`)

Add a small compatibility patch in the CJK-font section of `main.py` (project code only — no venv/site-packages edits):

- Wrap the four `*DrawParaLine` functions of `xhtml2pdf.reportlab_paragraph` with a helper that first coerces every word to UTF-8 bytes (`w.encode("utf-8")` for `str`, pass through `bytes`) without changing signatures, then calls the original.
- Because `drawPara` resolves the helper names from the module at draw time, patching the module attributes is sufficient and safe.
- Comment explains the xhtml2pdf bug and why the coerce happens.
